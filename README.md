# 宝可梦动态策略塔防系统（C++ / Qt Widgets）

> 面向对象程序设计（C++）课程项目 · 可运行的小型应用系统  
> 以塔防为载体，递进体现：类与对象 → 组合/依赖 → 继承派生 → 虚函数多态 → vector/模板 → 文件流。

---

## 1. 项目概况

- **技术栈**：C++17 + Qt Widgets（自绘渲染，无外部美术资源）
- **玩法**：宝可梦研究基地守护能量结晶，敌方宝可梦沿两条预定义路线进攻；玩家部署己方宝可梦，通过普通攻击、属性克制、属性附着与**连携反应**阻止敌人。
- **地图**：1 张二维地图（20 × 12 逻辑格），出生点 → **4 条路线**（上环 / 直通 / 下环 / 之字）→ 核心；  
  之字路线与直通路线形成两处路口。**道路格子不可部署**（`GameMap::isRoad()` 判定）
- **单位**：4 个玩家宝可梦（皮丘 / 小火龙 / 杰尼龟 / 妙蛙种子，**全部为最初形态**）、  
  3 种敌人（走路草 Basic / 霹雳电球 Fast / 拉普拉斯 Tank）
- **机制**：4 种属性、6 种连携反应、4 种目标策略、普通攻击、波次系统、金币、升级 / 出售、核心生命、胜负判定、存档读档

## 3. 编译与运行

### 方式 A：Qt Creator（推荐）

1. 安装 Qt（6.x 或 5.15，勾选 **Qt Widgets** 与 **MinGW / MSVC** 编译器）。
2. 打开 `PokemonTowerDefense.pro` 或 `CMakeLists.txt`，选择 Kit，点击运行（Ctrl+R）。

### 方式 B：CMake 命令行

```bash
cd PokemonTowerDefense
cmake -S . -B build -DCMAKE_PREFIX_PATH="<你的 Qt 路径>/lib/cmake"
cmake --build build --config Release
./build/PokemonTowerDefense        # Windows 下为 .\build\Release\PokemonTowerDefense.exe
```

### 方式 C：qmake 命令行

```bash
cd PokemonTowerDefense
qmake PokemonTowerDefense.pro
mingw32-make            # 或 nmake / make
```

> 本工程**未使用 Q_OBJECT**（无自定义信号槽，全部用 lambda 连接），因此不依赖 moc，构建更省心。

### 方式 D：无需 Qt 的核心逻辑验证（推荐先跑这个）

## 5.5 进化系统（实验三/四的进阶体现）

**进化链用"多层继承"表达**，每条链三级：

```text
皮丘 Pichu(172)   -> 皮卡丘 Pikachu(25)   -> 雷丘 Raichu(26)
小火龙 Charmander -> 火恐龙 Charmeleon(5)  -> 喷火龙 Charizard(6)
杰尼龟 Squirtle   -> 卡咪龟 Wartortle(8)  -> 水箭龟 Blastoise(9)
妙蛙种子 Bulbasaur -> 妙蛙草 Ivysaur(2)   -> 妙蛙花 Venusaur(3)
```

- **触发**：升级到 **3 级**进化为一阶、**5 级**进化为二阶（`Pokemon::nextEvolveLevel()`）。
- **钩子**：`Pokemon::nextStageId()` 是虚函数，每个形态返回自己的下一形态 id；  
  最终形态显式返回 `nullptr`（`Raichu` 不覆写就会错继承 `Pikachu` 的返回值——这正是  
  "多层级继承必须显式终结"的典型坑）。
- **对象替换**：`Game::tryEvolve(Pokemon*&)` 用 `createEvolved()`（内部走 `createPokemonById`  
  多态工厂）生成新形态对象，**整体替换**容器里的旧对象，再同步调用方持有的指针。  
  这也是为什么 `upgradePokemon` 的签名是 `Pokemon*&`（引用传指针）。
- **所有权**：旧对象的索敌策略通过 `takeStrategy()` 转移给新对象（`setStrategy` 会 delete  
  旧策略，直接赋值会导致双重释放）。
- **存档**：`SaveManager` 写的是 `getClassName()`，因此读档时 `createPokemonById("Raichu")`  
  能直接重建出最终形态（已实测：皮丘一路升到 5 级 → 存档 → 读档恢复 `Raichu Lv.5`）。
- **数值**：进化形态的基值更高（攻击/血量/范围/攻速），并继承等级成长；进化后回满血。
- **表现**：进化瞬间原地播放金色粒子 + "进化！"飘字，信息面板显示  
  `皮卡丘 Lv.4（一阶进化）` 与下一次进化的提示。

## 6. 答辩五句话（对应文档第 31 节）

1. `Pokemon` 与具体宝可梦用**继承**表达 is-a。
2. `Pokemon` 与 `TargetStrategy` 用**组合**，因为它们是独立变化的行为。
3. `TargetStrategy`、`Reaction` 通过**抽象基类 + 虚函数**实现运行时多态。
4. `vector<基类指针>` 统一管理不同派生类对象。
5. 文件流保存具体派生类型与对象状态，读取时重新构造并恢复多态容器。

## 7. 设计取舍说明

- **为什么不用 QML**：课程要展示纯 C++ 的类设计，QML 会把界面逻辑交给声明式语言，弱化 C++ OOP 展示；Qt Widgets + `QPainter` 自绘同样能获得良好视觉（霓虹发光、粒子、飘字、核心脉冲）。
- **Qt 不承担业务逻辑**：`GameWidget` 只负责绘制与输入，`MainWindow` 只用 `QTimer` 驱动 `Game::update()`；属性克制、连携反应、波次、金币等全在 `core/entity/battle` 中。
- **反应与附着分离**：`PokemonType`（固有属性）由 `TypeSystem` 处理克制；战斗中临时附着的 `ElementStatus` 与由此触发的 `Reaction` 由 `ReactionEngine` 负责，两者职责独立。
- **扩展性**：新增一种 `Reaction` 或 `TargetStrategy` 只需增加一个派生类并在工厂注册，无需改动已有的 `Pokemon`、`GameMap` 代码。

## 8. 原生素材与视觉表现

工程使用**宝可梦原生素材**（详见 `assets/README.md`）：

| 类别               | 来源                                                                  | 用途                        |
| ---------------- | ------------------------------------------------------------------- | ------------------------- |
| 宝可梦立绘            | PokéAPI sprites（官方立绘）                                               | 4 个玩家宝可梦 + 3 种敌人的单位贴图     |
| 属性徽章             | PokéAPI sprites（第八世代）                                               | 单位、敌人附着状态、部署按钮、底部信息栏      |
| 地图地面图块           | `pret/pokeemerald` 原始 tiles + metatiles + palettes                  | 草地、土路、树林边框、花丛点缀           |
| **界面窗口边框**       | `pret/pokeemerald` 的 `graphics/text_window/3.png` + `text_pal*.pal` | 全部面板的九宫格边框                |
| **像素字体**         | 缝合像素字体 Fusion Pixel Font 12px（OFL）                                  | 全局中英文文字                   |
| **TD 地表 / 技能特效** | `ElasticSea/PokemonTD`（elementalTD 风格）                              | 草地/道路/树/入口图块、投射物与序列帧、状态图标 |
| 地表变体             | 同上（从中挑 4 种低渐变草地 + 3 种树 + 花丛/灌木）                                     | 让地图不再大片重复                 |

地面图块不是直接拿来用的灰度图：原始 `tiles.png` 是 4bpp 索引数据，需要按  
**GBA BG 图块位序（0-9 位图块号、10/11 位翻转、12-15 位调色板号）** 配合游戏原始  
`palettes/*.pal` 组装成 metatile 才是真实上色的画面；草地再用绿宝石自身的草地绿调色板做色阶重映射。

界面边框同理：图块里**索引 0 是镂空色、中间 8×8 是填充色**，按 2 倍导出后以  
**九宫格（border-image slice 16）** 拉伸使用 —— 这正是 GBA 画窗口的方式，任意尺寸都不失真。

字体做了**子集化**：6.7 MB 的原始中文像素字体按界面实际用到的 545 个字符裁剪到  
**83 KB（TTF，Qt 用）/ 19 KB（WOFF2，网页内嵌）**。字号必须取 12 的整数倍（12/24/36）。

**渲染层**：`GameWidget` 用 `QPixmap` 缓存（按像素尺寸缓存缩放结果）绘制，  
单位带投影、血条、等级点、属性徽章；敌人血条上方显示附着属性徽章与异常状态点。  
找不到 `assets/` 时**自动退化**为程序化绘制（不会崩溃），并在画面左上角提示。

### 8.1 GBA 宝可梦风格界面

## 9. 普通攻击与家族成长

每次普通攻击使用面板攻击力，经属性克制和护甲结算；攻击间隔是唯一出手计时，没有独立技能威力和冷却。
普通攻击施加自身元素：草持续 4 秒，其余持续 8 秒，附着只记录元素和剩余时间，本身不造成伤害、减速、麻痹或灼烧。

| 家族 | 定位 | 每级攻击成长 | 每级射程成长 | 每级间隔乘数 | 家族特色 |
|---|---|---:|---:|---:|---|
| 皮丘 | 高频单体 | +2 | +0.08格 | 0.94 | 20%概率追加4+等级伤害 |
| 小火龙 | 范围清怪 | +5 | +0.08格 | 0.985 | 溅射半径1.4/1.6/1.8格，比例35/40/45%；灼烧2秒，每秒2/3/4点 |
| 杰尼龟 | 稳定控制 | +3 | +0.15格 | 0.98 | 减速随等级与形态成长，初始30%，最终44% |
| 妙蛙种子 | 远程破甲 | +6 | +0.22格 | 0.99 | 普通攻击忽略40/55/70%的护甲减伤比例 |

三段数值分别对应初始、一阶、最终形态；等级成长在进化后保留，3级和5级自动进化。
草系破甲作用于普通攻击，不作用于元素反应；火系溅射不附着元素。
水系减速比例为0.30+阶段×0.05+(等级−1)×0.01，持续时间为1.6+等级×0.15+阶段×0.2秒。
每级生命成长分别为电12、火20、水30、草22；当前敌人不攻击我方，生命不作为主要平衡收益。

## 10. 元素附着与六种反应

只保留火、水、草、电四种元素。附着本身不附加任何效果，伤害与控制由普攻家族特色、异常状态或元素反应产生。每个敌人最多一种附着：同元素刷新，异元素触发反应并消耗双方；六种异元素组合均有反应。

| 反应 | 组合 | 主目标 | 周围敌人 |
|---|---|---|---|
| 电导链 | 水+电 | 10伤害，麻痹3秒，停步判定概率35% | 无 |
| 燃烧 | 火+草 | 灼烧3秒，每秒4伤害 | 无 |
| 缠绕生长 | 水+草 | 减速40%，2.5秒 | 无 |
| 蒸汽爆发 | 火+水 | 8伤害，减速20%，1.5秒 | 半径1.5格，6伤害 |
| 能量爆破 | 火+电 | 12伤害 | 半径1.6格，12伤害 |
| 麻痹孢子 | 电+草 | 麻痹2.5秒，停步判定概率50% | 半径1.6格，4伤害 |

麻痹不再降低移动速度：先移动0.5秒再判定，成功停步0.25秒，之后必须移动至少0.5秒才能再次判定。
重复麻痹只刷新时长和保留较高概率，不重置判定/停顿计时；最大判定概率为50%，避免永久锁死。
相同减速只刷新并保留较强效果；减速可以与随机停步配合。
灼烧每0.5秒结算，保留小数伤害和计时；已修复每帧取整不扣血的问题，刷新不会清空累积。
反应伤害仍受护甲减免，范围伤害不重复打主目标、不附着、不继续引发反应。
反应特效按六种组合绘制，文字约0.3秒、特效约0.4秒。

更多参数、定位取舍与模拟结果见 [BALANCE.md](BALANCE.md)。

详情主卡展示预计单体秒伤、射程、出手间隔、下次出手倒计时、范围内敌人数、累计伤害；攻击说明显示家族特色，悬停可看面板攻击力。升级按钮下方用“攻击提高、射程扩大、出手更快”等文字说明实际提升，不再展示数值前后对比。
进化链最右侧排列，初始/一阶/最终形态分别标注 Lv.1、Lv.3、Lv.5；标注的是进入该形态的等级，当前实际等级显示在名字旁。


## 进度保存与读取

指令和战斗日志使用加粗文字。当前单位与状态统计的数值卡使用宝可梦对话框边框。
升级（达到形态门槛时显示“进化”）与出售按钮位于最右侧形态图上方，不再显示进化链标题。
我方宝可梦不会被敌人攻击，生命值目前不参与战斗；下次出手倒计时显示在独立卡片中。

存档固定为游戏程序所在目录的 `savegame.txt`，不再依赖启动时的工作目录。
V5 保存累计伤害，以及金币、分数、核心生命、完整出怪进度、敌人的道路位置与生命、元素附着与异常状态、我方形态等级、索敌策略、攻击计时、统计和暂停/胜负状态。
写入采用临时文件及原子替换，读取先校验完整存档再替换战场；失败时保留当前进度。
兼容 V2 存档，旧档未记录的单位累计伤害从零开始。V1 缺少敌人与出怪记录，只能从保存的波次重新出怪并保持暂停，点击“继续”开始。
开始游戏保留提前部署的宝可梦；“重新开始”会重置整局。

验证：`tests/persistence_rules.cpp` 检查战斗中、暂停、未开始、失败、胜利的完整存读档、12 个形态、攻击计时、旧存档、损坏文件隔离、原子覆盖和中文路径。


选中单位时以黄色箭头标出索敌策略选出的当前目标；已移除反应搭档说明和队友绿色虚线标记。预计单体秒伤未计克制、护甲、持续伤害、概率追击及反应；累计伤害记录攻击瞬间实际扣血（含溅射和即时反应，不含后续持续伤害），进化和读档保留。
`tests/unit_insights.cpp` 验证实际伤害归属、道路覆盖判断、升级进化迁移、V3 存档及 V2 兼容。

V5 额外保存灼烧内部计时、小数伤害及麻痹随机状态和停步计时；兼容V1–V4。旧冰附着/冻结迁移时移除，旧麻痹转换为随机停步，旧技能冷却忽略；较旧存档的我方生命按新版上限截断。
